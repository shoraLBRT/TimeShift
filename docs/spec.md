# ТЗ: бот учёта прожитого времени (MVP)

Название: **TimeShift**.
Версия: 0.4, 2026-11-14. Статус: согласовано, открыт один вопрос (раздел 12).

---

## 1. Цель и принципы

Вести учёт того, на что уходит время, **почти без ручного ввода**. Бот сам предзаполняет ленту дня, а пользователь только подтверждает или поправляет — кнопкой, текстом или голосом. Итог — честная статистика за день/неделю: сколько спорта, учёбы, отдыха, сколько залипания.

Принципы:

1. **В ленте нет дыр.** Каждая минута принадлежит какому-то отрезку.
2. **Ленивый ввод.** Чаще всего ответ — один тап. Текст и голос — для всего остального.
3. **Нейронка понимает, код считает.** LLM переводит фразу в структуру; границы, длительности, отсутствие пересечений считает и проверяет обычный код.
4. **Честность статистики.** У каждого отрезка есть статус уверенности, отчёт показывает, какая часть подтверждена.
5. **Клиент — это адаптер.** Telegram — первый клиент. Вся логика (включая диалоги разбора) живёт в ядре и доступна через API — для будущих Mini App / PWA / iOS.
6. **Сразу многопользовательский.** `user_id` во всех данных, часовой пояс у каждого пользователя.

## 2. Термины

| Термин | Что это |
|---|---|
| **Лента** | Непрерывная последовательность отрезков времени пользователя |
| **Отрезок** | Интервал `[начало, конец)` с занятием, категорией и статусом |
| **Занятие** | Что делал: «Тренировка», «Dota 2», «Дорога зал → дом». Знает свою типичную длительность и категорию по умолчанию |
| **Категория / подвид** | Классификация для статистики: «Залипание → Соцсети/короткие видео» |
| **Шаблон недели** | Расписание по умолчанию: ночь, день, постоянные блоки |
| **Постоянный блок** | Повторяющийся блок шаблона: учёба пн–пт 9:00–15:00, работа, свои |
| **Фон** | То, чем заполняется время, о котором ничего не известно: ночью — сон, днём — залипание, в постоянном блоке — этот блок |
| **Открытое занятие** | Занятие, о начале которого сказано, а о конце — ещё нет |
| **Факт** | Знание о пользователе: маршрут и его длительность, правило классификации, место |

## 3. Модель времени и правила заполнения

### 3.1. Статусы отрезка

| Статус | Значок | Откуда берётся | Что с ним делает бот |
|---|---|---|---|
| **Подтверждено** | ✅ | Пользователь сказал сам или подтвердил | Ничего |
| **Предположено** | ⚪ | Продление в пределах нормы, постоянный блок, ночной сон по шаблону | Переспрашивает одним вопросом «всё верно?» (в разборе) |
| **Под вопросом** | 🟡 | Превышение нормы, дневной фон | Обязательно разбирает — сразу, как пользователь появился, или в вечернем разборе |

### 3.2. Слои ленты (сверху вниз по приоритету)

1. **Явные отрезки** (✅) — то, что сказал пользователь.
2. **Продление открытого занятия** (⚪ → 🟡) — см. 3.3.
3. **Постоянные блоки** шаблона недели (⚪).
4. **Фон** суток: ночь → «Сон» (⚪), день → «Залипание» (🟡).

Фон и постоянные блоки **не хранятся** заранее — они вычисляются из шаблона при построении ленты. В базу записываются только явные отрезки и то, что пользователь подтвердил или поправил (материализация).

### 3.3. Продление открытого занятия

У занятия есть типичная длительность `T` (из фактов; если неизвестна — бот спросит один раз и запомнит). Пользовательские настройки задают два коэффициента:

- `norm_factor` — до `T × norm_factor` занятие продлевается как ⚪ (в норме);
- `max_factor` — от нормы до `T × max_factor` занятие продлевается как 🟡 (превышение);
- после предела — фон.

Пресеты настройки «режим продления»:

| Пресет | norm_factor | max_factor |
|---|---|---|
| До типичной длительности | 1.0 | 1.0 |
| **×1.5 норма, ×2 предел** (по умолчанию) | 1.5 | 2.0 |
| Бесконечно | ∞ | ∞ |
| Свой | любой | любой ≥ norm |

Если продление упирается в начало постоянного блока или ночи — оно всё равно продолжается до своего предела (явное занятие важнее шаблона), но отрезок внутри блока помечается 🟡.

### 3.4. Пример (из обсуждения)

Типичная тренировка `T = 60 мин`, пресет ×1.5 / ×2. В 14:00 пользователь пишет «тренируюсь» и молчит до 17:00.

```
14:00–15:30  Тренировка      ⚪ (в норме, ×1.5)
15:30–16:00  Тренировка      🟡 (превышение, до ×2)
16:00–17:00  Залипание (фон) 🟡
```

В 17:00 голосом: «тренировался только час, потом поехал домой, дома смотрел ютуб».

```
14:00–15:00  Тренировка               ✅
15:00–15:25  Дорога зал → дом         ✅ (25 мин — из факта о маршруте)
15:25–17:00  YouTube → ?              бот: «Это был отдых, учёба или залипание?»
```

Если факта «зал → дом» ещё нет — бот спрашивает: «Сколько обычно едешь из зала домой?», сохраняет ответ и пересчитывает.

### 3.5. Алгоритм разбора периода (детерминированный)

Вход: окно `[A, B]` (A — последний известный момент, B — «сейчас» или явная граница) и последовательность пунктов от LLM. У каждого пункта длительность задана одним из способов:

- явно: «час», «минут 20», «с 3 до 4»;
- через факт: маршрут, типичная длительность занятия;
- «остаток»: «всё оставшееся время»;
- не задана.

Правила:

1. Явные времена «с … до …» становятся якорями и делят окно на под-окна.
2. Пункты с явной длительностью и с фактами расставляются по порядку.
3. Ровно один пункт без длительности (или помеченный «остаток») забирает остаток окна.
4. Нужен факт, а его нет → вопрос пользователю, разбор ждёт ответа.
5. Больше одного пункта без длительности, или сумма не влезает в окно → бот уточняет.
6. Границы округляются до 5 минут.
7. Результат показывается как предложение с кнопками `✅ Верно` / `✏️ Поправить`; в ленту пишется после подтверждения (или после тайм-аута — как ⚪).

Это чистая функция в Domain — покрывается юнит-тестами.

### 3.6. Перерыв внутри занятия и параллельные занятия

**Перерыв.** Если внутри открытого занятия описан отрезок, который кончился раньше «сейчас», занятие после него
продолжается: «работаю» с 10:00, потом «с 13 до 13:30 обедал» → работа 10:00–13:00, обед, работа дальше с 13:30.
Время до перерыва засчитывается: норма и предел продления (3.3) считаются по сумме, а не от возобновления.
Занятие не продолжается, если описанный период доходит до «сейчас» (пример 3.4) или накрывает его начало.

**Параллельные занятия.** Два занятия могут идти одновременно: «ел и смотрел YouTube», «обедал за работой».
Лента тогда из двух дорожек:

- **основная** — непрерывная, без пересечений, сумма за сутки = 24 ч; основное занятие — то, что «шло само по
  себе» (работа, YouTube), его и считает статистика времени;
- **параллельная** — закрытые отрезки поверх основной (обед, переписка). Они не вытесняют основную ленту, могут
  пересекаться между собой и переживают правку основной дорожки.

Что основное, а что параллельное, решает LLM по формулировке («за работой», «пока смотрел», «и одновременно»);
если неясно — основное то, что началось раньше или длится дольше, параллельное — то, что короче. «Сейчас ем за
работой» записывается как параллельный отрезок на типичную длительность еды со статусом ⚪ — его можно поправить.

В `/day` параллельные занятия рисуются тонкой полосой поверх основной; в цифрах дня и недели они идут отдельной
строкой «параллельно» и в 24 часа не входят.

## 4. Категории и классификация

### 4.1. Стартовый набор (редактируется пользователем)

| Группа | Категории |
|---|---|
| Полезное | Работа · Учёба · Свои проекты · Спорт |
| Необходимое | Сон · Дорога · Быт (еда, готовка, уборка, гигиена, покупки) |
| Люди | Семья · Друзья |
| Отдых | **Осознанный отдых** — решил отдохнуть сам: тишина, прогулка, фильм, сериал, синглплеер-игры |
| Потерянное | **Залипание**: соцсети/короткие видео · YouTube · мультиплеер-игры · валялся · прочее |

### 4.2. Правила по умолчанию

| Что | Категория по умолчанию |
|---|---|
| Фильмы, сериалы | Осознанный отдых |
| Короткий контент (Shorts, Reels, TikTok, лента соцсетей) | Залипание |
| YouTube (обычные видео) | **Спросить**: отдых / учёба / залипание — пользователь говорит явно |
| Игры | **Спросить про конкретную игру один раз и запомнить**: Dota 2, CS → залипание; синглплеер → отдых |
| Неизвестное занятие | LLM предлагает категорию, бот подтверждает кнопками |

Каждое правило — это факт пользователя (`classification_rule`), который бот пополняет из ответов. Пользователь всегда может переопределить конкретный отрезок: «нет, этот ютуб был учёбой».

## 5. Сценарии

### 5.1. Онбординг (первый запуск)

Пошаговый диалог; на каждом шаге можно ответить кнопкой, текстом или голосом.

1. Часовой пояс (по умолчанию Москва, кнопки).
2. **Ночь:** «Во сколько обычно ложишься и встаёшь?» → блок «Сон». Можно разное для будней и выходных.
3. **День:** всё, что вне ночи, по умолчанию — фон «Залипание» (поясняем пользователю, зачем).
4. **Постоянные блоки:** «Есть учёба/работа по расписанию?» → «учёба пн–пт 9–15, по субботам до 13» → LLM разбирает в блоки → подтверждение. Повторять, пока пользователь не нажмёт «Готово».
5. **Свои блоки:** любые повторяющиеся (тренировки по вт/чт и т. п.).
6. Интервал пингов (5–240 мин; кнопки 15 / 30 / 45 / 60 / 90 / 120 или число) и режим продления (пресеты 3.3).
7. Итог: картинка шаблона недели, «Можно поменять в любой момент: /blocks, /settings».

### 5.2. Пинг

- Раз в `ping_interval` бот спрашивает «Чем занят?» с кнопками: `То же самое`, 3–5 последних/частых занятий, `Другое…`.
- **Во время открытого занятия** первый пинг — по достижении типичной длительности (`T`), далее — по интервалу. Кнопки: `Всё ещё <занятие>`, `Закончил`, частые.
- **Не пингуем:** во время сна по шаблону, в тихие часы, во время постоянного блока (опционально — настройка).
- **Без ответа:** предыдущий неотвеченный пинг удаляется при отправке нового (чат не засоряется). После `max_unanswered` (по умолчанию 2) неотвеченных — пауза до первого сообщения пользователя.

### 5.3. Ответ

- **Кнопка** → открывает/продлевает/закрывает занятие, LLM не вызывается.
- **Текст / голос** → (голос → распознавание) → LLM → намерения (раздел 8) → код применяет → бот показывает результат и, если нужно, уточняет.

### 5.4. Разбор жёлтых участков

- **Сразу**, как только пользователь написал после пропуска: «Пока тебя не было: 15:30–17:00 под вопросом. Что было?»
- **Вечерний разбор** перед сном: за `evening_review_offset` до обычного сна по шаблону, или когда пользователь пишет «ложусь спать». Показывает картинку дня, перечисляет оставшиеся 🟡 по одному, затем ⚪ одним списком: «Остальное верно?» → `Да` / `Поправить`.
- **Утром** (первое сообщение дня): «Спал как обычно, 1:00–9:00?»

### 5.5. Уточняющие вопросы бота

Бот хранит очередь невыясненного (неизвестная длительность маршрута, категория новой игры, тип YouTube) и задаёт **не больше одного вопроса за раз**, в удобный момент (сразу после ответа пользователя, а не отдельным пингом).

### 5.6. Записи задним числом

Записать можно любой прошедший период, не только «сейчас»: в 6 утра — за вчерашний вечер, в понедельник — за
выходные.

- **Текстом / голосом (через LLM):** «вчера с 19 до 21 был в зале», «вечером смотрел сериал часа два»,
  «в субботу с 12 до 15 гулял с друзьями». В контекст LLM уходит текущее время и пояс, поэтому «вечером» в 6 утра —
  это вчерашний вечер, а «ночью» — прошедшая ночь. Намерение — `describe_period` с датой (раздел 8).
- **Без LLM (запасной путь и для точности):** `/add` → «Что и когда? Например: вчера 19-21 Зал». Понимает
  «сегодня / вчера / позавчера», день недели («в субботу» — последняя прошедшая суббота), дату «13.11», диапазон
  времени и название; несколько строк — несколько записей.
- **Из ленты:** `/day вчера` (или `/day 13.11`) показывает ленту того дня; под ней кнопки «➕ Добавить» и
  «🟡 Разобрать под вопросом» — запись идёт в выбранный день.
- **Правила:** запись в прошлом применяется так же, как обычный период (3.5, 3.6): режет и вытесняет то, что было,
  сохраняется как ✅ и попадает в журнал `/undo`. Будущее не записывается (это план — итерация 3). Если диапазон
  неоднозначен («с 11 до 2» в 6 утра), бот переспрашивает. Открытое занятие, начатое до периода, после него
  продолжается, если период кончился раньше «сейчас» (3.6).

### 5.7. Команды

| Команда | Что делает |
|---|---|
| `/day [дата]` | Картинка ленты дня + цифры по категориям; `вчера`, `13.11` — другой день |
| `/add` | Записать прошедший период: «вчера 19-21 Зал» (5.6) |
| `/now` | Что сейчас идёт; сменить или закончить занятие |
| `/week` | Картинка недели по категориям + доли ✅/⚪/🟡 |
| `/quiet 2ч` или «не беспокой 2 часа» | Ручные тихие часы |
| `/blocks` | Посмотреть и изменить шаблон недели |
| `/settings` | Интервал пингов, режим продления, вечерний разбор, провайдер LLM |
| `/facts` | Что бот знает: маршруты, длительности, правила классификации |
| `/undo` | Откатить последнее применённое изменение ленты |

## 8. Контракт с LLM

**Вход** (собирается кодом): текущее время и часовой пояс, лента за сегодня (сжато), открытое занятие, известные занятия/места/маршруты/категории, последний вопрос бота (если пользователь на него отвечает), текст сообщения.

**Выход**: строгий JSON — список намерений. Модель ничего не считает, только извлекает.

| Намерение | Поля |
|---|---|
| `start_activity` | activity, at?, place? |
| `stop_activity` | at? |
| `describe_period` | date? (сегодня, если не сказано), from?, to?, items: [{activity, category_hint?, duration_min?, start?, end?, route?: {from, to}, fill_rest?, parallel?}] — `parallel: true` у занятия, которое шло одновременно с основным (3.6) |
| `answer` | to_question_id, value (да/нет/число/категория/текст) |
| `classify` | activity, category |
| `set_fact` | kind, data (маршрут, типичная длительность и т. п.) |
| `quiet` | minutes / until |
| `edit_segment` | target (время/описание), changes |
| `unclear` | question — что переспросить |

Код валидирует JSON по схеме; при ошибке — одна повторная попытка, затем «Не понял, скажи иначе» с кнопками. Набор из 30–50 реальных фраз пользователя с ожидаемым результатом — **тестовый набор** для выбора модели и регрессии промпта.

## 9. Архитектура

### 9.1. Решение (.NET 10)

```
TimeShift.sln
src/
  TimeShift.Domain          сущности, построение ленты из слоёв, продление,
                             разбор периода (3.5); без внешних зависимостей
  TimeShift.Application     сценарии (сообщил занятие, разбор, онбординг, пинги,
                             итоги), интерфейсы: ILlmProvider, ISpeechToText,
                             INotifier, IClock, репозитории
  TimeShift.Infrastructure  EF Core (SQLite для разработки → PostgreSQL),
                             LLM-провайдеры, распознавание речи, рендер картинок
  TimeShift.Telegram        адаптер Telegram: апдейты → сценарии, INotifier → сообщения
                             с кнопками
  TimeShift.Host            ASP.NET Core: REST API для будущих клиентов + фоновые
                             сервисы (пинги, вечерний разбор) + Telegram в одном процессе
tests/
  TimeShift.Domain.Tests
  TimeShift.Application.Tests
```

Ключевое: Application говорит на языке «задать вопрос с вариантами», «показать предложение ленты». Telegram рисует это кнопками; будущая PWA / iOS — своими экранами и пушами. Логика не дублируется.

### 9.2. Компоненты

| Что | Чем |
|---|---|
| Telegram | Telegram.Bot (long polling на старте, webhook позже) |
| Планировщик | BackgroundService: раз в минуту выбирает пользователей с `next_ping_at <= now` (переживает перезапуски) |

| Развёртывание | Docker Compose на VPS: приложение + PostgreSQL |

## 10. Ограничения: Россия

Пользователь платит из России, VPS планировался в России. Это меняет выбор провайдеров.

### 10.1. Telegram — главный риск

По новостям на 2026-11-13, работу Telegram в России ограничивают с лета 2025, с февраля 2026 — сильнее; полной блокировки нет, но доступность сильно зависит от региона. **Сервер бота в России может не достучаться до Telegram Bot API.**

**Решение:** VPS за рубежом (Нидерланды, Финляндия, Германия и т. п.) у хостера, принимающего оплату рублями. Сервер видит и Telegram, и зарубежные API. На стороне пользователя Telegram работает через VPN — для целевой аудитории в России это норма, клиентом остаётся Telegram.

Запасной вариант:
- Архитектура не завязана на Telegram (9.1): запасной клиент — **PWA** (веб-приложение «на экран Домой», без App Store; пуши на iPhone работают с iOS 16.4) или бот в другом мессенджере.

### 10.2. LLM

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Агрегаторы с оплатой в рублях** (ProxyAPI, AITunnel, Polza AI и др.) | OpenAI-совместимый API, доступ к Claude Haiku / DeepSeek / Qwen, оплата картой РФ / СБП | Наценка; надёжность у разных сервисов разная |
| **GigaChat API** (Сбер) | Для физлиц есть бесплатный режим (лимиты уточнить на developers.sber.ru); работает из РФ | Свой формат API; один поток; качество разбора проверить |
| **YandexGPT** (Yandex Cloud) | Рубли, работает из РФ | Платно; проверить цены |
| Напрямую Anthropic / OpenAI / Groq | — | Из России без зарубежной карты и обхода блокировок недоступно |

Расходы на LLM при любом выборе — порядка рубля-десятков рублей в месяц на пользователя (≈30 запросов в день по ≈3 тыс. токенов). Выбор — по качеству на тестовом наборе (раздел 8).

### 10.3. Распознавание голоса

- **Локально на VPS: whisper.cpp (Whisper.net)** — бесплатно, без блокировок, хороший русский. Нужен VPS ~2–4 vCPU / 4 ГБ RAM. **Выбор по умолчанию.**
- SaluteSpeech: по документации Сбера, подключение новых клиентов закрыто с 15.07.2026 — не рассматриваем.
- Облачный Whisper через агрегатор / Yandex SpeechKit — как запасной вариант.
